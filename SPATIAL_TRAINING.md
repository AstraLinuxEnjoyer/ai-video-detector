# Обучение первой модели

Новый запуск обучает только EfficientNet V2-S. Temporal и третья ветвь не изменены. Старые веса в `models/` и старые манифесты в `cache/spatial/` сохраняются. Новые веса не подменяют модель FastAPI автоматически: для неё потребуется подключение того же preprocessing и агрегации после проверки качества.

## Одна команда

Открой PowerShell в `C:\Users\Ivan\Desktop\ai-video-detector` и запусти:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spatial.ps1
```

Этот запуск:

1. Находит рабочий Python. Если старый `venv` ссылается на отсутствующий Python312, использует совместимый локальный Python 3.12 и уже установленные пакеты проекта. Новые пакеты в системное окружение не устанавливаются.
2. При первом запуске сканирует `data/real` и `data/fake`, переиспользует DeepAction из кэша и пытается скачать недостающие файлы DeepAction. При сетевой недоступности сохраняет причины и использует доступные данные. Другие источники автоматически не выдумываются и не получают метки из предположений.
3. Считает SHA-256, объединяет точные копии, группирует известные связанные клипы, сохраняет train/val/test и отдельный отложенный источник OpenSora. Первый аудит десятков тысяч файлов может занять заметное время; хеши кэшируются в SQLite.
4. Готовит кадры, затем обучает модель. Между эпохами меняется выборка видео и кадров. Во время GPU-обучения сеть для датасетов не нужна.
5. Сохраняет лучшую модель, останавливается по отсутствию улучшений либо после заданного числа эпох. Затем проверяет лучшие веса на test, отложенном источнике и тесте H.264-пережатия. Если есть `test_videos/real` и `test_videos/fake`, автоматически проверяет и эти личные тестовые видео.

Повтор **той же команды** продолжает последний запуск. Веса, optimizer, scheduler, AMP scaler, случайность, очереди видео и позиция внутри эпохи восстанавливаются из checkpoint. Он записывается каждые 50 шагов и на границах этапов. При аварии последние несохранённые шаги выполнятся заново из предыдущего сохранённого состояния. Во время validation завершённое обучение эпохи повторять не нужно.

Чтобы намеренно начать отдельный эксперимент:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spatial.ps1 --fresh
```

Старые эксперименты не перезаписываются. Обычному продолжению `--fresh` не нужен. Если текущий запуск уже закончен, команда не начинает бессрочное новое обучение.

## Что используется по умолчанию

| Параметр | Значение |
| --- | --- |
| Инициализация | ImageNet-веса EfficientNet V2-S, новая бинарная голова |
| Изображение | 384 x 384, crop без чёрной рамки, ImageNet normalization |
| Train batch / val batch | 8 / 8, AMP на CUDA |
| Эпохи | До 20; early stopping после 5 эпох без улучшения |
| Видео на эпоху | До 1000, поровну real/fake, квоты по источникам |
| Кадры train / val | 4 случайных / 8 фиксированных на видео |
| Validation / test | До 800 видео в каждом фиксированном контрольном наборе |
| Отложенный источник | GenVideo_OpenSora и связанные с ним группы |
| Разминка | 1 эпоха только головы; далее размораживается backbone |
| LR backbone / головы | 0.00002 / 0.0001 |
| Новый кэш кадров | До 20 GiB на запуск |
| Докачка DeepAction | До 20 GiB добавления при первоначальной подготовке |
| Резерв диска | 10 GiB, дополнительное место учитывается при checkpoint |

Пул train больше одной эпохи. Квоты не вырезают большие датасеты из пула: очереди проходят все видео источника перед новым циклом. Малые источники могут повторяться раньше больших. Ни 20 эпох, ни early stopping не гарантируют обход всего каталога: фактический охват виден в `coverage.json`.

## Автоматизация датасетов

Автоматическая докачка реализована только для `faridlab/deepaction_v1`. Уже скачанные файлы используются повторно, лимиты диска проверяются заранее. Если сеть недоступна, попытки ограничиваются и обучение может использовать имеющиеся локальные файлы. Во время обучения новые видео из сети не скачиваются.

Для VideoUFO, GenVideo, GenVidBench и других добавляемых источников скачивание и распаковка архивов остаются ручными. Программа не обходит регистрацию, условия доступа и лицензии. Сейчас ничего дополнительно скачивать не нужно: существующие папки уже учтены.

Новые видео кладутся в `data/real/<название_источника>/` или `data/fake/<название_источника>/`. Поддерживаемые контейнеры: MP4, MOV, AVI, MKV, WEBM, M4V; возможность чтения конкретного кодека проверяет FFmpeg. Архив, CSV или parquet сам по себе видео для этого загрузчика не заменяет. Не смешивай настоящие и сгенерированные записи под неправильной меткой. Для нового источника со связанными вариантами одних роликов нужно дополнить правила группировки до включения в эксперимент.

После добавления датасета нужен новый эксперимент: обычный `--fresh` начинает обучение с ImageNet, а `--parent-run` позволяет дообучать лучшую модель предыдущего эксперимента с сохранением его разделов данных (см. ниже). Уже идущий запуск использует неизменный снимок. Вручную извлекать кадры, делать prefetch и вызывать старый prepare_dataset не нужно.

## Проверка своих видео

Внешние видео не должны участвовать в обучении. Папки:

```text
test_videos/real/iphone/your_video.mov
test_videos/fake/generator_name/generated_video.mp4
```

Подпапки с названием камеры или генератора необязательны, но дают отдельные метрики по источникам. Метка из папки используется только для подсчёта ошибок: модель получает изображение, а не имя папки.

После завершения хотя бы одной эпохи с validation останови обучение и запусти:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spatial.ps1 --evaluate-only --input .\test_videos
```

Команда возьмёт `best.pt` последнего нового запуска с тем же preprocessing и запишет `external_report.json`, `external_predictions.csv` и `training.log` в его подпапку `external/<дата_время>/`. Она не обучает модель и не меняет её веса. При совпадении хешей с обучающими файлами отчёт помечается как несамостоятельная проверка. Старый скрипт оценки со своими преобразованиями для новых весов не рекомендуется.

Для другой сохранённой модели нового формата укажи `--run-dir <папка_запуска>`. Восемь личных видео полезны для поиска ошибок, но недостаточны для утверждения, что модель распознаёт определённый процент всех видео.

Переинициализация от ImageNet выбрана из-за утечек в прежнем разбиении. Старый checkpoint нельзя считать чистым относительно нового test. Технически дообучение своих весов поддерживается:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spatial.ps1 --fresh --init-model models\spatial_best.pt
```

Такой запуск явно помечается как имеющий неизвестное предыдущее знакомство с контрольными данными. Для основного нового эксперимента рекомендуется обычная команда без `--init-model`.

## Где результаты

Каждый запуск находится в `cache/spatial_v2/runs/<дата_время>/`. Его полный путь выводится строкой `RUN`. Последний путь также записан в `cache/spatial_v2/latest.json`.

- `training.log`: стадии подготовки, настройки, квоты, обучение, валидация, ошибки и итог.
- `environment.json`: версии Python, PyTorch, torchvision, CUDA, GPU, seed и отпечаток разбиения.
- `data_summary.json`, `splits.json`: точный состав разделов, источники и отпечаток разбиения.
- `data_errors.jsonl`: недоступные загрузки, ошибки хеширования/декодирования, причины карантина.
- `validation_ids.json`: контрольный набор, зафиксированный до первого обновления весов, и исключения на подготовке.
- `epoch_001_plan.json`: ID реально запланированных видео, числа по классам и источникам.
- `batches.jsonl`: loss, learning rates, нормы градиентов, изменение весов головы, ожидание данных, пиковая CUDA-память.
- `epoch_001_metrics.json`, `epochs.jsonl`: train/val, ошибки по источникам, AUROC, average precision, F1, ложные тревоги, полнота обнаружения, распределения оценок и доверительный интервал по группам видео.
- `epoch_001_val.csv`: прогноз каждого проверенного validation-видео.
- `coverage.json`: использованные ID и охват каждого источника; запланированное не засчитывается как обученное до успешного шага optimizer.
- `metadata_only_baseline.json`: контрольный классификатор только по размерам, FPS, длительности и приблизительному битрейту, без изображения. Высокий результат означает, что в наборе есть простые технические подсказки.
- `best.pt`, `best.json`: лучшие веса и параметры их применения, включая preprocessing, агрегацию и порог.
- `last.pt`, `checkpoint.pt`: последние полностью оценённые веса и состояние для продолжения.
- `final_report.json`, `test_predictions.csv`, `ood_predictions.csv`: итоговая проверка, не участвовавшая в выборе лучшей эпохи.
- `compression_original.csv`, `compression_crf32.csv`: парные прогнозы до и после H.264 CRF32.

В логе есть прогресс стадий; живые полосы прогресса выводятся в консоль. Дублировать каждое движение полосы в файл не нужно: файл содержит события и численные результаты. Для разбора обычно достаточно `training.log`, `data_summary.json`, `epochs.jsonl`, `coverage.json`, `final_report.json` и CSV с ошибками. Они доступны в директории проекта.

## Как читать результаты

Ненулевые градиенты и изменение весов подтверждают работу optimizer. Они не доказывают обобщение на новые видео. Для этого сравниваем validation, test, отложенный источник и пережатие; отдельно смотрим ложные fake на реальных записях.

100% train или высокий val не являются автоматическим доказательством ошибки. При val от 98% выдаётся диагностическое предупреждение. Важно, какой результат на неизвестном источнике и не решается ли задача по одним метаданным. Подбирать параметры по закрытому test нельзя.

Агрегация новой модели: средняя оценка восьми кадров. В отчёте есть стандартный порог 0.5 и отдельно порог, выбранный на validation для не более 5% ложных тревог на её real-видео. На других данных тот же уровень ложных тревог не гарантирован. Оценка sigmoid без калибровки не является достоверной вероятностью происхождения видео.

Для OOD-набора только из fake AUROC и balanced accuracy остаются пустыми: сообщается полнота обнаружения, а не выдуманная двухклассовая accuracy.

## Проверка фотографий без меток

Клади фотографии прямо в `photo_check/`, без разделения на real и fake. Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\check-photos.ps1
```

Для каждого изображения выводятся REAL/FAKE, имя и fake_score. Используются лучшие веса текущего spatial_v2-запуска; эпоха указана в консоли. По умолчанию расчёт на CPU, без изменения обучения или checkpoint. Порог фото 0.5: порог от средней оценки видеокадров автоматически не переносится на одиночные фотографии. Оценка не является калиброванной вероятностью.

Поддерживаются JPG, PNG, WEBP, BMP и TIFF; HEIC/RAW нужно экспортировать в JPG/PNG. Файлы не изменяются, в обучение не попадают и игнорируются Git. Команда каждый раз проверяет все изображения в папке. JSON-отчёт сохраняется в `reports/photo_check_<время>.json`, включая эпоху и хеш весов. Подробнее: [photo_check/README.md](photo_check/README.md).

## Ошибки и ресурсы

Переполнение FP16-градиентов обрабатывается повтором того же батча с уменьшенным масштабом AMP. После двух неудачных FP16-попыток используется один расчёт FP32; постоянные нечисловые значения по-прежнему останавливают запуск. Неудачные попытки не засчитываются как обучение, BatchNorm и случайность восстанавливаются перед повтором. Диагностика записывается в `numerics.jsonl`. Разбор первой реальной эпохи и исправленного сбоя: [SPATIAL_REVIEW_2026-09-26.md](SPATIAL_REVIEW_2026-09-26.md).

FFmpeg декодирует по времени, учитывает поворот и переводит распознанный HDR в SDR. Декодирование ограничено таймаутами. Неподдерживаемое или повреждённое видео не заменяется соседним. Оригиналы не перекодируются и не удаляются.

До обучения допускается карантин не более 2% ошибок выбранных файлов с записью причин. Validation фиксируется после подготовки; при последующем изменении её доступности запуск останавливается. Ошибки в закрытом test приводят к статусу incomplete, а не к публикации улучшенной accuracy на оставшихся файлах. Изменение исходника после хеширования останавливает запуск и требует нового аудита, а не маскируется как допустимый пропуск.

Автоматически удаляются только кадры законченной train-эпохи внутри каталога текущего запуска. Старые запуски, исходники и вручную скачанные датасеты остаются. Не забывай, что 20 GiB кэша кадров и 20 GiB возможной докачки являются отдельными бюджетами, а старые эксперименты тоже занимают место.

При CUDA OOM можно уменьшить batch и продолжить тот же запуск:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spatial.ps1 --batch-size 4 --val-batch-size 4
```

Позиция сохранена в кадрах, поэтому изменение batch не заставляет начинать весь эксперимент заново. Другие содержательные параметры и разбиение заморожены; для их изменения нужен новый запуск.

При добавлении новых датасетов нужен новый снимок: `--fresh` либо новая папка `--run-dir` с `--parent-run` для дообучения. В существующий эксперимент новые файлы незаметно не добавляются. Для работы без сети при новой подготовке есть `--offline`.

## Дообучение с DAVIS и KoNViD, 27 сентября 2026

Подготовлен эксперимент `cache/spatial_v2/runs/20260927_davis_konvid_sora_kling`.
Он начинает с `best.pt` 15-й эпохи эксперимента `20260926_202651_279558`, а не с ImageNet и не с последней эпохи.

Запуск и возобновление из корня проекта одной и той же командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spatial.ps1 --run-dir cache/spatial_v2/runs/20260927_davis_konvid_sora_kling
```

`--fresh` к этой команде добавлять не нужно. Настройки уже записаны: до 12 эпох, 2000 клипов/эпоху (1000 real + 1000 fake), 4 кадра/клип, batch 8, 384x384, AMP. Обучается вся сеть; LR backbone 5e-6, classifier 2e-5. Optimizer/scheduler новые, исходные веса обученные. Остановка после 5 эпох без улучшения video balanced accuracy. Сеть дообучается на новых и старых источниках с равными квотами между источниками внутри класса, пока хватает уникальных клипов. Маленький источник не дублируется внутри одной эпохи.

Изображения напрямую преобразуются в кэш PNG, без сборки в MP4. Проверка отслеживает изменение/добавление/удаление кадров. FPS и длительность не выдумываются.
- `data/real/KoNViD_1k_videos`: обычные видео с меткой real.
- `data/fake/OpenAI_Sora` и `data/fake/keling`: обычные видео с меткой fake, включая вложенные I2V/T2V.
- Все прежние источники сохраняются. На первом обходе каждого источника приоритет у видео, не использованных родительской best-моделью. Далее работает обычная ротация.
- Старые train/val/test/OOD закреплены по хешам, группам и известным путям. Если новые дубликаты связывают два прежних раздела, подготовка останавливается. Кадры DAVIS группируются по сцене, а не распределяются независимо.
- Родительская модель сначала проверяется на новом фиксированном validation. Результат записывается в `initial_val.json`, исходные веса сохраняются как best эпохи 0. Последующее обучение заменяет best только при улучшении на том же validation. Старые веса и логи не перезаписываются.
- `lineage.json` фиксирует родительский запуск, эпоху, SHA256 весов и ранее использованные ID. Отчёт каждой эпохи различает охват текущего запуска и охват вместе с родителем.
- Режим offline использует локальные файлы и уже скачанный DeepAction-кэш; новых сетевых загрузок нет.
- Metadata-only baseline и тест пережатия работают только с настоящими видеоконтейнерами; число исключённых последовательностей JPEG явно записывается. DAVIS участвует в обычных train/val/test проверках.

Логи: `training.log` (одновременно консоль и файл), `initial_val.json`, `epoch_*_metrics.json`, `epoch_*_plan.json`, `batches.jsonl`, `numerics.jsonl`, `data_errors.jsonl`, `coverage.json`, затем `final_report.json`. Наличие high validation accuracy само по себе не доказывает перенос на новые телефоны. Старые контрольные результаты уже обсуждались, поэтому они не являются новым слепым тестом.

Аудит завершён: 81718 уникальных записей, train 61715, val 7770, test 7395, OOD 4838. Все 80109 записей родительского снимка сохранили свой раздел. Из новых источников в train/val/test соответственно: DAVIS 72/10/8, KoNViD 950/127/123, OpenAI_Sora 42/2/6, keling 216/28/25. Один точный дубликат Sora объединён. Очень маленькая Sora-validation не позволяет надёжно оценить качество отдельно на этом генераторе.

Проверка плана первой эпохи: 2000 уникальных записей, поровну real/fake, 1372 ранее не использованы выбранной родительской моделью. Для каждого следующего плана точный состав будет в `epoch_*_plan.json`.

Интеграционный тест `cache/spatial_v2/smoke/finetune_20260927_170207` успешно прочитал 6 train и 6 val записей, выполнил три обновления весов EfficientNet на RTX 5060 Ti, validation и сохранение. Переполнение AMP восстановлено повтором, включая FP32; пик выделенной PyTorch памяти около 3.58 GiB. Все веса конечны. Это проверка исполнения, не измерение качества: среди шести контрольных примеров исходная модель ошиблась на реальной сцене DAVIS. Основной эксперимент этим тестом не обучался, исходные best-веса не изменены.

Для будущего набора данных можно подготовить другой эксперимент, указав другую новую папку и `--parent-run` существующего завершённого эксперимента. Не менять файлы уже подготовленного снимка; для добавлений нужен новый снимок.

## Что проверено и что не обещается

31 автотест проверяет точные дубликаты и конфликт меток, разделение связанных видео, чередование и возобновление очередей, метрики с одинаковыми оценками, выбор порога, воспроизводимость аугментаций, восстановление optimizer после прерывания, обновление кэша, изменённые исходники, картинки с расширением видео и противоречие метки известному источнику. Включены тесты восстановления после численного сбоя AMP, чтения DAVIS без масок, закрепления родительских разделов и сохранения исходной best-модели при отсутствии улучшения. Короткий отдельный GPU smoke-test проверяет EfficientNet, реальные видео, разминку/разморозку, validation, checkpoint, пережатие и личные тестовые видео. Его цифры не являются оценкой качества модели. На RTX 5060 Ti проверен batch 8 при 384 x 384 с AMP, включая полную разморозку: пик выделения памяти PyTorch около 1.87 GiB, не включая все внешние расходы CUDA и других программ.

Не выполняется исчерпывающий поиск всех визуально похожих перекодированных копий; проверяются хеши и известные группы происхождения. Метки источников наследуются из каталогов/официальной структуры, а не проверяются человеком автоматически. OpenSora-проверка не заменяет независимый набор новых реальных камер. Детектирование коротких вставок и любых локальных нейросетевых правок не гарантируется этой схемой целого видео.

После окончательного аудита отдельно проверено чтение 36 видео из всех 18 источников (по два на источник): 36 успешно, 0 ошибок. Это выборочная техническая проверка, а не гарантия исправности всех 80109 видео. Отчёт: `cache/spatial_v2/decode_checks/20260926_202829/report.json`. Позднее пользователь запустил основное обучение; результаты первой эпохи и продолжение после численного сбоя описаны в отдельном разборе выше.
