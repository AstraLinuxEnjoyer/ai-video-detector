## 2. Быстро запустить демонстрацию

На исходном компьютере из корня проекта:

```powershell
.\start-demo.cmd
```

Адрес по умолчанию: http://127.0.0.1:8787. При занятом порте скрипт выбирает
свободный и печатает адрес. CPU по умолчанию, обучение не запускается.
При проверке 11 октября сайт уже был запущен отдельным скрытым процессом;
после перезагрузки его нужно запустить снова. Наличие сервера проверять, а не предполагать.

На другом Windows x64:

1. Перенести `releases/TRACE-demo-windows.zip`, распаковать.
2. Установить Python 3.12 x64, запустить `setup-demo.cmd` в распакованной папке.
3. После установки зависимостей запустить `start-demo.cmd`.

Первичная установка требует сети. ZIP включает две модели и FFmpeg/FFprobe,
но не готовый Python и не виртуальное окружение. Это не автономный EXE-установщик.
Чистая установка на отдельном компьютере ещё не проверена.
Подробности: [DEMO_GUIDE.md](DEMO_GUIDE.md).

Для пересборки архива на исходной машине:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\export-demo.ps1
```

Демо использует замороженный экспорт `demo_weights`, поэтому новое обучение
не обновляет запущенный сайт автоматически. После изменения весов остановить
сайт, сделать экспорт, запустить снова.

## 3. Какие модели действительно используются

| Ветка | Исходные лучшие веса | Эпоха | Вход |
|---|---|---:|---|
| Spatial | `cache/artifact_spatial/runs/hybrid_v2/best.pt` | 5 | EfficientNet V2-S: общий кадр и локальные области |
| Motion | `cache/temporal_v2/runs/motion_flow_v1/best.pt` | 10 | R(2+1)D-18: двухканальный оптический поток, не RGB |

Экспорт для сайта: `demo_weights/spatial.pt`, `demo_weights/temporal.pt`,
`demo_weights/manifest.json`. В манифесте находятся рецепт, настройки и SHA256.
Контрольные суммы на дату снимка:

```text
spatial:  31d044b02eaaedaf6b7b54015a0ad72a10c4257afa4aabd81a617dfb9e21f3a5
temporal: 496d44a48ff7dba03e8a321e853a762b8c65c0546d95ed4868792657a417d927
```

Не путать с историческими `models/spatial_last.pt`, `temporal_last.pt` или
RGB-экспериментом `r2plus1d_v1`. Название `last` означает последнее сохранение,
а не лучшую проверенную модель. Для демонстрации выбраны `best` указанных запусков.

Motion-рецепт: 9 RGB-кадров при 4 FPS дают 8 полей dx/dy, размер входа 112,
декодирование 128, Farneback с вычитанием медианного глобального потока,
фиксированной нормализацией скорости. OpenCV **5.0.0** закреплён в конфигурации.
Несовместимую версию не обходить без проверки воспроизводимости.

## 4. Реальные измерения и ограничения

Spatial `hybrid_v2`, внутренний test: 800 видео, 400 real + 400 fake.
Accuracy 95.375%, recall fake 92.75%, FPR на real 2%, AUROC 0.99555.
OOD: 800 fake, recall fake 91%; это **не** двухклассовая accuracy.
В `coverage.json` этого запуска отмечены 10 465 уникальных обучающих ID.
Это не количество всех видео проекта и не суммарное покрытие всех прошлых запусков.

Motion `motion_flow_v1`, test: запрошено 800, оценено 568, без ответа 232.
Accuracy среди оценённых 81.16%, balanced accuracy 76.58%, recall fake 64.41%,
FPR 11.25%. TP=114, TN=347, FP=44, FN=63.
OOD: оценено 482/800, recall fake 64.32%; набор fake-only, FPR неизвестен.
Основная причина исключений: недостаточная длина клипа, например 1.6 или 2 секунды
при требовании 2.25 секунды. Coverage motion: 3459 уникальных ID из 17 150 eligible.

Эти тесты уже использовались при разработке: **не свежий слепой benchmark**.
Нельзя объявить 95% точности на любых пользовательских видео. Вторую модель
нельзя считать автоматически улучшающей первую: нужен тест ансамбля на общих ID.

В сайте смесь score 70% spatial + 30% motion является эвристикой, не обученным
и не откалиброванным ансамблем. Heatmap показывает чувствительность fake-logit
общего spatial-вида, а не доказательство редактирования или человеческое объяснение.
Карты потока показывают настоящий вход motion-ветки, не причинную интерпретацию.
Интервалы сайта грубые; обученного pixel-mask или точного segment-localizer пока нет.

## 6. Что не переносится через Git

`.gitignore` исключает данные, веса, кэши, окружения, отчёты и загрузки.
Клон репозитория содержит код и документы, **не содержит обученные модели**.

| Локальные данные | Назначение |
|---|---|
| `data/real`, `data/fake` | Рабочие обучающие источники, ещё на диске C |
| `D:\dataset` | Перемещённые скачанные архивы/распаковки |
| `datasets/archive` | Junction на `D:\dataset`, не переносится Git |
| `datasets/CocoGlide` | Junction на `C:\Users\Ivan\Downloads\CocoGlide` |
| `datasets/FakeParts` | Отдельно скачанные файлы внутри проекта |
| `cache/*/runs/*` | Чекпоинты, конфигурации, splits, планы, логи и coverage |
| `test_videos/real`, `test_videos/fake` | Ручные тесты пользователя |
| `photo_check` | Ручная проверка изображений |
| `demo_weights`, `demo_runtime`, `releases` | Экспорт, результаты сайта, переносной ZIP |

Перемещение архивов на D **не** освобождает автоматически место рабочих файлов
`data` на C. Не удалять `data`, думая, что обучение уже полностью переехало.
Между C и D нельзя сделать NTFS hardlink. Копирование должно быть явным.
Корень архива можно переопределить `AI_VIDEO_ARCHIVE_ROOT`.

Для запуска демо достаточно ZIP. Для точного продолжения обучения нужны данные
и весь соответствующий run, а не один `best.pt`: optimizer/scaler/counters,
splits/config/lineage и родительские артефакты. В frozen-файлах есть абсолютные
пути исходной машины. Миграция обучения на другое устройство ещё не автоматизирована;
нельзя массово заменить строки и заявить, что split/lineage сохранились.

## 7. Команды обучения и проверки

Это справочник, **не инструкция автоматически запускать долгую тренировку**.
На исходном компьютере после проверки среды:

```powershell
# Spatial hybrid: продолжение своего run, не новый старт с нуля
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-classifier.ps1

# Проверка фото из photo_check
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-classifier.ps1 --predict-images

# Ручные видео из test_videos/real и test_videos/fake
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-classifier.ps1 --evaluate-only

# Motion-only, отдельный от RGB run
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-temporal.ps1 -MotionTrain

# Историческая RGB temporal-ветка, НЕ motion-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-temporal.ps1
```

Оба актуальных запуска уже завершены. Повтор команды не обещает дополнительные
эпохи сверх frozen-конфигурации/early stopping. Новый эксперимент создавать
отдельно с документированным parent и причинами изменения, не затирать старый.
`--fresh` не нужен для обычного resume. Восстановление идёт от durable checkpoint;
часть работы после последнего сохранения может повториться.

Логи: `cache/artifact_spatial/runs/hybrid_v2/training.log` и
`cache/temporal_v2/runs/motion_flow_v1/training.log`. Смотреть также `best.json`,
`epochs.jsonl`, `coverage.json`, `numerics.jsonl`, decode-отчёты, predictions CSV
и `final_report.json`, а не только строку accuracy в консоли.

На исходной машине launcher `venv/Scripts/python.exe` был неисправен;
PowerShell-обёртки умеют использовать совместимый bundled Python 3.12.
На другом компьютере создать нормальное окружение, не ожидать этот путь Codex.
Для тестов с работающим Python и зависимостями:

```powershell
$env:OMP_NUM_THREADS='2'
$env:MKL_NUM_THREADS='2'
python -m unittest discover -s tests -p 'test_*.py'
```

11 октября прошёл 91 unit-тест. Реальные browser-проверки проведены через
Playwright/system Edge на desktop и mobile; `tests/demo_browser_smoke.cjs`

5. Начать отдельную ветку частичного вмешательства с парными оригиналами,
   редакциями и масками/временными границами: CocoGlide/FakeParts сначала аудитировать.
   Эти новые наборы пока не входят в существующие frozen-training runs.
6. Оценивать локализацию по IoU/временным метрикам, не по Grad-CAM и video accuracy.
7. Третья ветка camera/noise/metadata только после доказательства добавочной пользы;
   отсутствие шума/метаданных само по себе не означает генерацию.
