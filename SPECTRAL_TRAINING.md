# Спектральная модель TRACE

## Кадр и лицо на всём train

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spectral.ps1 --faces
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spectral.ps1 --faces --dashboard --port 8771
```

Новый запуск `spectral-face-v3` в `cache/spectral/runs/spectral_face_v3`.
По умолчанию в него входят **все видео из старого зафиксированного train**
и все варианты **обучающих семейств DFDC**, а не 400 роликов. Валидируем и
тестируем на прежних отложенных разделах и бюджете 160/240/120. JPEG-последовательности
DAVIS в этот видеоэксперимент не входят. Разметка известного спорного ролика
про робота не используется в train. Дубликаты DFDC сверяются по SHA256 со
старым пулом и между собой; конфликтующие семейства исключаются с записью
в снимок. Для подготовки без обучения добавь `--prepare-only`.

Масштабирование происходит **только для детектора лица**. YuNet находит
наибольшую подходящую область; спектр и остаток считаются по исходным
пикселям этого прямоугольника, без увеличения маленького лица.
Один и тот же детектор используется для обоих классов. Рамка в мониторе
показывает выбранную область, а не маску подмены. Для части кадров лицо
может быть выбрано неверно или не найдено вовсе.
Веса [OpenCV Zoo YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)
скачиваются один раз (~230 КБ, MIT), сверяются по SHA256 и остаются в локальном кэше.

В отчёте сравниваются прежние три варианта по всему кадру, «только лицо»
и «кадр + лицо». Последний усредняет две оценки в отношении 1:1 и при
отсутствии лица использует только кадр. Это гипотеза для эксперимента,
не новый вердикт TRACE. У оценки только по лицу есть покрытие, а в JSON
также сохранены метрики по совпадающему подмножеству с обнаруженным лицом.
Вклад классов, источников и групп оригиналов балансируется весами:
ролики не выбрасываются только ради баланса.

Основной запуск на CPU может занять десятки часов. Остановка Ctrl+C и
повтор той же команды переиспользуют хэши и уже готовые признаки.
Исходные видео не копируются. Для короткого эксперимента укажи отдельный
`--run-dir` и ограничение `--train`. Старый запуск без `--faces` сохранён.

## Полнокадровый baseline

`spectral-full-frame-v2` реализует частотный и шумовой анализ из §1.2.2,
таблицы 1.1 и §1.3 диплома. Это отдельный CPU-baseline, не третий голос
в действующем TRACE. Spatial и temporal не дообучаются и не меняются.

## Запуск

Из корня проекта, в первом PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spectral.ps1
```

Во втором PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spectral.ps1 --dashboard
```

Открыть http://127.0.0.1:8767 либо свободный порт из консоли. Панель локальная,
только для чтения; можно открыть до обучения или после него. Она показывает
размеры выборок и долю DFDC, прогресс декодирования, кэш, пропуски, кадр
и его спектр, метрики и журнал. После обучения и выбора порога видны ответ
REAL/FAKE, score ролика и порог; метка датасета подписана отдельно.
Кадр в панели показывает канал яркости, уменьшенный только для просмотра.
Вместо фиктивных эпох
отображается обучение трёх вариантов логистической регрессии.

Нужны Python 3.12, зависимости обучения проекта и `ffmpeg`/`ffprobe` в PATH.
По умолчанию используются `cache/artifact_spatial/runs/hybrid_v2/splits.json`
и `~/Downloads/dfdc`. Сменить расположение DFDC можно `--dfdc-root` или
`AI_VIDEO_DFDC_ROOT`; сменить базовый split можно `--parent-splits`.
Видео не скачиваются, не копируются и не изменяются.

## Как работает

1. Читаются `metadata.json` всех частей DFDC; проверяется наличие файлов
   и настоящих оригиналов для всех FAKE. Индекс сохраняется в
   `cache/datasets/dfdc.json`. Только индекс: `train-spectral.ps1 --index-only`.
2. Старые разделы не меняются. Семейства DFDC назначаются в train/val/test
   по ссылке на оригинал; один оригинал и все его варианты в одном разделе.
   Это не гарантирует разделение по актёрам. По умолчанию 400/160/240 видео
   train/val/test, до 25% DFDC в каждом: по одному REAL и одному FAKE на
   выбранное семейство. OOD (до 120 видео) из старого отложенного раздела.
   SHA256 выбранных DFDC-видео проверяется против всей старой выборки
   и других выбранных файлов. Используется видео, а не JPEG-последовательности DAVIS.
3. В трёх фиксированных временных точках декодируется яркость **всего кадра**
   в нативном разрешении, без вырезания участков и без увеличения маленьких
   кадров. Нормированная энергия 2D FFT по десяти полосам и статистики остатка
   после Gaussian blur дают 30 признаков на видео. RGB и метаданные не подаются
   в модель. Ограничения: SDR, стороны от 16px и не больше 4096×2304 пикселей
   по площади.
4. Обучаются три L2-регуляризованных классификатора: спектр, остаток и вместе.
   Порог каждого выбирается на чистой validation под целевой FPR 5%.
   Это цель на этой выборке, не обещание для новых данных. На тех же test ID
   проверяется одинаковое JPEG quality 70 каждого кадра с прежним порогом.
   Это покадровый контроль, не видеопережатие H.264.
5. Несовместимый размер/HDR или ошибка декодирования видны в отчёте без подмены
   файлов. Изменение источника после фиксации останавливает запуск. Повтор той же
   команды переиспользует признаки и заново обучает классификаторы. Для других
   настроек нужен новый `--run-dir` (тот же путь передать панели).

## Результаты

`cache/spectral/runs/spectral_full_frame_v2`: `training.log`, `final_report.json`
(по источникам и с ранжированием пар DFDC), `predictions.json`, `model.json`,
`*_coverage.json`, `live.json`. Сохраняется только один уменьшенный кадр
в живом снимке панели, отдельный кэш кадров не создаётся.
Старый вариант из пяти зон доступен с `--patches` и сохраняется в прежней
папке `spectral_residual_v1`. Фичи и веса двух вариантов не смешиваются.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-spectral.ps1 --predict "C:\path\video.mp4"
```

Комбинированная модель возвращает score, не откалиброванную вероятность.
Шумовой остаток не равен PRNU. Нет идентификации камеры и пиксельной
локализации. JPEG-контроль не исключает влияние исходного кодека, разрешения
и датасета. Перед подключением к TRACE нужны новые источники, видеопережатие
и сравнение ансамбля на общих ID при сопоставимой доле ложных тревог.

## Полный кадр в первых двух ветках

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-classifier.ps1 -FullFrame
powershell -NoProfile -ExecutionPolicy Bypass -File .\train-temporal.ps1 -FullFrame
```

Запускать последовательно: пространственная и временная ветки используют
общий lock. Первая берёт текущие лучшие hybrid-веса как стартовые, но получает
один полный вид 224×224 вместо смеси с кропами. Вторая запускает отдельный
flow run от Kinetics: целые кадры приводятся к 128×128 перед вычислением
потока, а на этапе обучения поток больше не кропается до 112×112, а целиком
масштабируется. Оба квадратных входа сохраняют всё поле зрения, но не исходное
соотношение сторон. Прежние runs, их метрики и веса сайта TRACE не меняются.
Новые папки: `cache/artifact_spatial/runs/full_frame_v1` и
`cache/temporal_v2/runs/motion_full_frame_v2`. DFDC пока подключён только
к спектральной ветке.
